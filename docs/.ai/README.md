# AI Agent向けドキュメント

このディレクトリには、AI Agent（Claude Code、Junie、JetBrains AI Assistant）がプロジェクトで作業する際のガイドラインとプラクティスが含まれています。

## 目的

AI Agentが以下を行うための明確で構造化された指針を提供します：

- プロジェクトの設計原則とパターンを理解する
- 確立されたプラクティスに沿ったコードを書く
- チームの基準と一貫性のある判断を下す
- コードベースを効果的にナビゲートする

これらのドキュメントはAI支援開発の基盤であると同時に、人間の開発者にとっても有用なリファレンスとなります。

## ディレクトリ構成

```text
<project-root>
└── docs/.ai/
    ├── README.md                     # このファイル（人間向け、日本語）
    ├── guidelines.md                 # AI Agent向けインデックス（英語）
    ├── design-practices.md           # 設計原則（英語）
    ├── testing-practices.md          # テスト原則（英語）
    ├── coding-practices.md           # コーディング原則（英語）
    ├── kotlin-practices.md           # Kotlin固有のプラクティス（英語）
    ├── rust-practices.md             # Rust固有のプラクティス（英語）
    ├── typescript-practices.md       # TypeScript固有のプラクティス（英語）
    ├── {lang}-examples.md            # コード例（必要に応じて作成、英語）
    └── {lang}-examples/              # コード例（必要に応じて作成、コード例の数が多くなってきた場合、英語）
```

## ファイルの種類と役割

### Practicesファイル (`*-practices.md`)

**目的**: 原則、パターン、および判断の「なぜ」を定義する

**特徴**:
- 概念と理由に焦点を当てる
- 意思決定のための文脈を提供
- Agentが新しい状況に適応できるようにする
- 比較的安定している

**抽象度レベル**:
1. **design-practices.md** - 言語やドメインには依存しない
   - コア設計原則（DDD、境界、依存方向）
   - 要求、設計、実装の全フェーズで適用可能
2. **testing-practices.md** - 言語やドメインには依存しない
   - 普遍的なテスト原則（AAAパターン、命名、境界テスト）
   - 要求分析からunit/integration/e2eテストまで適用可能
3. **coding-practices.md** - 言語やドメインには依存しない
   - 言語をまたがる実装原則
   - イミュータビリティ、null安全性、エラーハンドリングなどの概念
   - 言語によって実現方法は異なる
4. **{lang}-practices.md** - ドメインには依存しないが言語固有
   - 特定言語での普遍的原則の適用方法
   - 言語イディオムとエコシステムの慣習
   - 依然として「なぜ」「いつ」に焦点、「どのように」だけではない

### Examplesファイル (`*-examples.md`)

**目的**: プラクティスの具体的な実装を示す

**特徴**:
- 具体的なコードサンプル
- 「良い」vs「悪い」の比較
- 従うべき具体的なパターン
- 必要になってから作成（事前には作らない）

**作成タイミング**:
- プラクティスが確立され安定してから
- 設計と実装の接続が複雑な場合
- チームが具体的な参照パターンを必要とする場合
- 新メンバーのオンボーディング時

## Practicesファイルの構造化

Practiceファイルは、開発プロセスを以下のような軸でレイヤー分割して適用範囲を整理しています。
ある作業をする場合にはその作業の属するレイヤーとその上位レイヤーのPracticeを参照する必要があります。
このディレクトリのプラクティスは、これらすべての次元にわたってドメインによらずに一貫して適用される**横断的関心事**です。

### 実装プロセス軸

Requirements → Specification → Design → Implementation (Coding) → Language

### テストプロセス軸

Requirement Analysis → Scenario → Data Pattern → Implementation → Unit, Integration, E2E

### アーキテクチャ軸

Domain → Application → Presentation, Infrastructure

## ドメイン固有のコンテキスト

`docs/.ai/`にはプロジェクト全体のプラクティスが含まれますが、ドメイン固有の知識は各ドメインと一緒に配置されます。

たとえば、ユーザードメイン、注文ドメイン、シェアードカーネルがあるプロジェクトでは以下のようになります：

```
src/
├── user-context/
│   └── docs/
│       └── .ai/
│           └── context.md  # ユーザードメインのルール、ユビキタス言語、コンテキスト境界
├── order-context/
│   └── docs/
│       └── .ai/
│           └── context.md  # 注文ドメインのルール、ユビキタス言語、コンテキスト境界
└── shared-kernel/
    └── docs/
        └── .ai/
            └── context.md  # 共有概念と値オブジェクト
```

**ドメインコンテキストファイルの内容**:

- 境界付けられたコンテキストのスコープと責任
- コアドメインルールと不変条件
- ユビキタス言語（ドメイン固有の用語）
- 主要な集約、エンティティ、値オブジェクト
- ドメインイベント
- コンテキストの依存関係と統合ポイント

## メンテナンス

### 新しいプラクティスの追加

1. **適切なファイルを更新**:
   - [ディレクトリ構成](#ディレクトリ構成)を参照して、適切なファイルを更新
2. **guidelines.mdを更新**:
   - Available Practice Filesセクションに追加
   - Loading Matrixを更新（必要な場合）
3. **このファイル (README.md)を更新**:
   - 新しいファイルタイプやパターンを導入した場合のみ

### Examplesファイルの作成

1. プラクティスが安定するまで作成しない
2. 自明でないプラクティスの適用例を示す
3. 焦点を絞り、最小限に保つ
4. 対比のため、良いパターンと悪いパターンの両方を示す

### 言語サポートの追加

1. `{lang}-practices.md`を作成
2. `guidelines.md`の「Language-Specific Practices」セクションに追加
3. このファイル (README.md) の[対応言語](#対応言語)セクションを更新

## 対応言語

現在サポートされている言語：

- **Kotlin**: JVMバックエンドサービス
- **Rust**: コマンドラインアプリケーション、パフォーマンスクリティカルなコンポーネント、システムプログラミング
- **TypeScript**: フロントエンドとNode.jsサービス

各言語には独自の`-practices.md`ファイルがあり、以下をカバーしています：

- 言語のイディオムと慣習
- エコシステムのベストプラクティス
- その言語で普遍的原則を実現する方法
- 一般的なパターンとアンチパターン

## 設計思想

これらのドキュメントは以下の原則を体現しています：**原則を教え、レシピは教えない**

明確な原則を持つAI Agentは：

- 新しい状況に適応できる
- 文脈に応じた適切な判断ができる
- コードベース全体で一貫性を保てる
- 理解が深まるにつれてコードを進化させられる

普遍的原則、言語固有のプラクティス、具体例を分離することで、AI Agentと人間の開発者の両方に効果的に機能する階層的な知識ベースを構築します。

## よくある質問

**Q: なぜ英語と日本語が混在しているの？**

AI Agent向けドキュメント（guidelines.md, *-practices.mdなど）は英語で記述されています。
これはLLMのトークン効率と理解精度のためです。一方、このREADMEは人間の開発者向けなので日本語で記述しています。

**Q: 新しいPracticeファイルを追加したらどうすればいい？**

`guidelines.md`を更新するだけです。各AI Agentの設定ファイルは`guidelines.md`を参照しているため、自動的に新しいファイルが利用可能になります。

**Q: PracticesとExamplesの違いは？**

Practicesファイルに記載されているプラクティスは、「**なぜ**」「**いつ**」に焦点を当てた原則です。
一方でExamplesファイルに記載されるサンプルは「**どのように**」を示す具体的かつ実践的なサンプルです。
プラクティスを先に確立し、必要になってからサンプルを作成してください。

**Q: ドメイン固有のルールはどこに書けばいい？**

各境界付けられたコンテキストの`docs/.ai/context.md`に書いてください（例：`src/user-context/docs/.ai/context.md`）。
プロジェクト全体のドキュメントは`docs/`に、ドメイン固有の知識はそのドメインの近くに配置します。
AI Agent向けのドキュメントは各ドキュメントディレクトリ内に`.ai`ディレクトリを作成して配置します。
