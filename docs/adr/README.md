# アーキテクチャ決定記録（ADR）

このディレクトリには、KoDoGu プロジェクトのアーキテクチャ決定記録（ADR: Architecture Decision Records）が含まれます。

## ADR とは？

アーキテクチャ決定記録は、重要なアーキテクチャ決定とその背景・結果を記録します。ADR は以下を可能にします：

- なぜその決定が行われたかを理解する
- 将来の変更のための文脈を提供する
- トレードオフと検討した代替案を文書化する
- 新しいチームメンバー（AI エージェントを含む）のオンボーディング

## フォーマット

各 ADR は以下の構造に従います：

- **タイトル**: 短い説明的な名前
- **ステータス**: 提案中 | 承認済み | 非推奨 | 置換済み
- **背景**: 取り組んでいる課題
- **決定**: 提案・実施される変更
- **結果**: 何が容易になり、何が困難になるか

## 新しい ADR の作成

1. テンプレートをコピー（利用可能な場合）、または既存の ADR を参考にする
2. 連番で番号付け（次に利用可能な番号）
3. ファイル名は英語（kebab-case）: `NNNN-descriptive-title.md`
4. すべてのセクションを記入
5. プルリクエストの一部として提出
6. この README を新しいエントリで更新

## ADR を書くべきとき

以下について決定する際に ADR を書く：

- アーキテクチャパターンや原則
- 横断的関心事
- 複数モジュールに影響する技術選択
- アーキテクチャ哲学を反映したコーディング規約

詳細なガイドラインは [ADR-0001](0001-record-architecture-decisions.md) を参照。
